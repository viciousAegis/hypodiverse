# Boolean Causal Micro-Lab v2: Current Results

This document records the fixed `final_v2` evaluation and the analysis commands
used for the thesis. It is an analysis record, not a claim that the current
training methods improve diversity.

## Evaluation design

- Frozen evaluation set: `eval_sets/causal_micro_lab/final_v2/verl_test.jsonl`
- States: 192, with 48 states for each `M` in `{4, 8, 12, 16}`
- Generation bank: 16 independent completions per state
- Reported prefixes: `K` in `{4, 8, 12, 16}` from the same completion bank
- Primary diversity metric: Predictive Diversity Recovery (PDR), conditioned
  on the state having at least one valid generated hypothesis
- Confidence intervals: paired or ordinary state bootstrap, as appropriate
- Model runs: base Qwen3-4B, Validity GRPO, IPS-GRPO, and Latent-IPS v2

The W&B evaluation-report artifacts are downloaded by:

```bash
python scripts/download_causal_micro_lab_v2_reports.py
```

The analysis and thesis figures are regenerated by:

```bash
MPLCONFIGDIR=/tmp/cml-matplotlib \
  python scripts/analyze_causal_micro_lab_v2_results.py
```

## Headline results

`Pass@K` and valid-output rate are unconditional. PDR and every other diversity
or coverage statistic are conditional on success. Paired diversity comparisons
use only states on which both methods succeed.

| Method | Pass@4 | Valid rate@4 | PDR@4 given success | Pass@16 | Valid rate@16 | PDR@16 given success |
|---|---:|---:|---:|---:|---:|---:|
| Base | 0.677 | 0.344 | 0.060 | 0.906 | 0.366 | 0.079 |
| Validity GRPO | 0.844 | 0.568 | 0.118 | 0.953 | 0.562 | 0.109 |
| IPS-GRPO | 0.880 | 0.618 | 0.112 | 0.964 | 0.604 | 0.105 |
| Latent-IPS v2 | 0.766 | 0.486 | 0.105 | 0.932 | 0.509 | 0.092 |

At `K=16`, Validity GRPO improves PDR over the base model by `0.028` on
their 168 common successful states (paired 95% CI `[0.002, 0.055]`). Neither
diversity-oriented method reliably improves PDR over Validity GRPO:

- IPS-GRPO minus Validity GRPO: `-0.004` (`[-0.031, 0.022]`; 179
  common successful states).
- Latent-IPS v2 minus Validity GRPO: `-0.010` (`[-0.040, 0.019]`; 172
  common successful states).

IPS-GRPO does improve the valid-output rate over Validity GRPO by `0.043` at
`K=16` (`[0.008, 0.078]`), but its exact-coverage and PDR intervals overlap
zero. The defensible conclusion is therefore that IPS primarily improves
validity in this run; it does not demonstrate additional predictive diversity.

## Validity and diversity decomposition

On the 85 states where every method returns at least two unique valid modes at
`K=16`, relative generated-to-available pairwise separation is:

| Method | Relative pairwise separation |
|---|---:|
| Base | 0.893 |
| Validity GRPO | 0.942 |
| IPS-GRPO | 0.932 |
| Latent-IPS v2 | 0.765 |

This conditional analysis separates two mechanisms: finding valid hypotheses
at all and spreading valid hypotheses across predictive behavior. Latent-IPS v2
underperforms on the second mechanism in the common comparison subset.

## Continuous separation

The continuous plots stratify by `M` and bin only for visualization. The
underlying analysis remains state-level. `separation_association.csv` reports a
bootstrap slope for each method, `K`, and `M`: the expected PDR change for a
`0.1` increase in available predictive separation. These curves use only states
where all four methods succeed, so every method is compared on the same support.
There is no consistent positive relation at `K=16`. This should not be described
as evidence that separation is irrelevant. PDR is normalized by the diversity
available in each state, so a flat PDR curve means a method recovers a similar
fraction of the opportunity as the opportunity changes.

## Reference-policy context

The CPU reference policies are privileged diagnostic anchors because they
sample directly from the verifier's valid mode set. They are not model
baselines. At `K=4`, their PDR ranking is:

| Policy | PDR@4 |
|---|---:|
| Oracle dispersed | 1.000 |
| Uniform distinct | 0.833 |
| Uniform sampling | 0.545 |
| Validity GRPO | 0.118 |
| IPS-GRPO | 0.112 |
| Latent-IPS v2 | 0.105 |
| Base | 0.060 |
| Concentrated sampling | 0.042 |
| Collapsed | 0.000 |

The large gap between model policies and uniform valid-mode sampling shows that
the benchmark has substantial headroom and distinguishes validity from mode
coverage.

## Verbalized-sampling evaluation

The final remaining test-time baseline asks for four candidates in one
completion. Its maximum response budget is `4 x 6000 = 24000` tokens, matching
the cap of four independent samples. The same `final_v2` states, SGLang memory
fraction (`0.82`), thinking mode, and fallback path are used.

Base model:

```bash
EVAL_CONFIG=configs/verl/eval/causal_micro_lab_verbalized_sampling_k4_v2.yaml \
  sbatch scripts/cluster/sbatch_causal_micro_lab_verbalized_sampling_eval.slurm \
  Qwen/Qwen3-4B 4 causal_micro_lab_final_v2_vs_k4_base
```

Validity-GRPO checkpoint, resolved and merged automatically:

```bash
EVAL_CONFIG=configs/verl/eval/causal_micro_lab_verbalized_sampling_k4_v2.yaml \
  sbatch scripts/cluster/sbatch_causal_micro_lab_verbalized_sampling_eval.slurm \
  causal_micro_lab_cluster_validity_grpo_r1 4 \
  causal_micro_lab_final_v2_vs_k4_validity
```

The `K=8` config is exploratory because its 30,000-token cap is constrained by
the model context and is not a strict `8 x 6000` token-cap match. Any comparison
must report actual generated tokens.
